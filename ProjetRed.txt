# Plan de Projet — Projet RED

Jeu CLI en **Go**, réalisé en équipe de **2**, suivi via un board GitHub Projects
(colonnes : *Truc à faire* → *Truc en cours* → *Trucs buggés* → *Done*).

Rendu attendu : dépôt Git nommé `projet-red_NOM-DU-PROJET`, contenant `src/`,
`docs/` (document de gestion de projet) et un `README.md` complété.

---

## 1. Répartition des rôles

**Développeur A — « Personnage, Inventaire & Économie »**
Possède : `Character`, `Equipment`, l'inventaire, le marchand, le forgeron, l'argent.
→ Porte directement le critère *« Économie et crafting »* (8 pts) et une partie de
*« Structure logique du jeu »* (6 pts).

**Développeur B — « Combat, Sorts & Progression »**
Possède : `Monster`, le combat tour par tour, les sorts, les missions de
progression (XP, mana, initiative).
→ Porte directement le critère *« Mécaniques de gameplay »* (8 pts) et l'autre
partie de *« Structure logique du jeu »*.

Les critères *« Univers thématique »*, *« Initiative personnelle »* et
*« Présentation »* sont partagés : le thème doit rester cohérent sur les deux
branches, et l'oral se prépare à deux.

Avec cette répartition, chacun porte ~11 pts/20 « en propre », le reste (thème,
bonus, oral) se construit à deux — la charge est équilibrée.

## 6. Points de synchronisation à prévoir

- **T10 (sorts) ↔ Marchand (Dev A)** : Dev B code `spellBook`, Dev A ajoute l'item
  « Livre de Sort : Boule de Feu » dans son marchand et appelle la fonction.
- **T21 (combat) ↔ Inventaire (Dev A)** : le combat doit pouvoir lire/consommer
  l'inventaire du joueur (ex. potions).
- **M4 (mana) ↔ Marchand (Dev A)** : ajout de la « Potion de mana » côté Dev A.
- **T22.2 ↔ Menu principal (Dev A, T6)** : ajout de l'option « Entrainement ».
- Fusionner les branches régulièrement (au moins à chaque tâche terminée) pour
  limiter les conflits sur `character.go`, qui est touché par les deux.
